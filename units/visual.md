# Visual Unit

Mirror source: `kernel-source.json`

## Role

Visual unit owns visible deliverables, but it no longer treats HTML-to-PPTX conversion as the default PPT road.

Covered deliverables:

- native editable PPTX
- browser HTML decks
- UI and web prototypes
- charts, diagrams, infographics, and supporting visuals
- motion demos when explicitly required

## Distilled visual atoms

Only these distilled atoms remain active here:

- `huashu-design` remains source-pool-only, never a second runtime
- `awesome-design-md` remains source-pool-only as a cold design-prior-art index
- `html-native-design-canvas`
- `brand-asset-protocol`
- `anti-ai-slop-visual-rules`
- `taste-skill` and `opencv-style` strengthen visual review only as source-pool lessons
- `design-direction-triad`
- `native-pptx-master-route`
- `motion-stage-sprite-engine`

Rule:

- `native-pptx-master-route` is the default deck atom
- `html-native-design-canvas` is for browser-native surfaces or explicit HTML deck work
- hyperframes lessons are already folded into `html-native-design-canvas`,
  `motion-stage-sprite-engine`, `anti-ai-slop-visual-rules`, and
  `native-pptx-master-route`; they do not remain as a separately mounted atom
- awesome-design-md may inspire direction, spacing, component density, and
  design-system brief structure only after brand/IP and attribution review; it
  never authorizes copying a third-party brand or loading a long DESIGN.md body
  into resident context.

## Modes

| Mode | Use when | Hard gate |
|---|---|---|
| Native PPTX | any PowerPoint deliverable | must stay editable in PowerPoint |
| HTML deck | browser presentation explicitly wanted | must verify in browser |
| UI prototype | web/app/interface work | must verify real view states |
| Data visual | charts/reports/comparisons | must read at a glance |
| Motion demo | animation/video/staged motion | must have motion evidence |

## PPT boundary

- PPT work follows [pptx_master.md](E:/wuji-projects/wuji-legion-codex/units/pptx_master.md).
- HTML deck does not stand in for PPT.
- HTML may inspire visual direction, but it does not own the PPT main chain.
- COM refine belongs only to the last mile.

Fallback rule

- Agnes image/video mirror failure may fall back only to the default GPT route.
- Local placeholders, local drawing, or proxy-blocked stand-ins cannot be reported as model output.

## Anti fake-fusion rules

Reject:

- HTML pretending to be editable PPTX
- screenshot PPT pretending to be native PPT
- decorative visual complexity with no information gain
- generic AI visual defaults
- route language that implies there are two equal PPT main chains
- hyperframes or any visual source pool becoming a second design runtime
