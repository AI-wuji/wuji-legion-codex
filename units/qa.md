# 质监局 + 白帽纠察 - 独立第三方审查体系

## 核心定位

审查体系不能并入执行者。

无极军团保留三个独立审查入口：

- `白帽纠察官`：执行前和执行中封驳错误路线。
- `质检主帅`：执行后验收成品是否可交付。
- `性能基准官`：用数据判断速度、成本、token、性能是否真的变好。

这三者不属于内容、视觉、开发等执行师团。

---

## 白帽纠察官

### 触发

- 复杂任务、规则重构、skill蒸馏、成品生成前。
- 用户明确点名白帽。
- 发现路线跑偏、半成品、硬塞模板、没实践就下结论。

### 工作链

```text
复述目标
-> 找前提和隐藏假设
-> 提出风险/反对意见
-> 判定放行/退回
-> 给最小修正方向
```

### 直接否决

- 没看源码就说已蒸馏。
- 没验证就说已成功。
- 用户要最终结果却交半成品。
- 用流程口号代替执行。
- PPT文字硬塞模板、HTML冒充PPTX、只给提示词冒充成图。
- 执行者试图自己审自己。
- 复杂任务只有“参谋本部接管”口号，没有 packet / result / verification 证据。
- 参考 PPTX 任务没有先锁定 `reference-frame-map`、`reusable-asset-map`、`illustration-plan` 就准备批量生成。
- 真 PPTX 任务的实现方案准备每页渲染成整图再塞回 PPT。
- 参考 deck 明显是重插图、重案例、重信息图风格，但生成计划没有同等级插图/案例/公式图安排。
- 没做 pilot page 或 pilot page 未过线，就准备批量生成 PPT/HTML 视觉成品。

## 质检主帅

### 非代码交付验证预算

- PPT、文档、图片、HTML演示稿、课程材料等非代码成品，先产出方向正确的成品，不能把错误路线跑完再验收。
- 开工前只查文件存在、输出路径安全、参考文件只读。
- PPT 参考任务开工前必须完成页型映射、素材复用和插图计划；这属于路线锁定，不属于工具链连环体检。
- PPT/HTML 视觉成品批量生成前必须有 pilot page 预览和 pilot-score。
- 不做工具链连环体检；工具失败后才局部验证并修复。
- 同一能力通过一次后不得重复验证。
- 10 分钟没有主成品文件，判定执行节奏失控，退回主线生成。
- 15 分钟仍在读文档、查接口、找字体、试 API、小原型或反复声明“马上生成”，判定口头执行、实际绕路，退回主线生成。

### 通用验收

- 产物是否存在。
- 路径是否明确。
- 是否可复现。
- 是否满足用户原目标。
- 是否有残余风险说明。
- 复杂 `LEGION_TASK` 是否有可审计轨迹：contract、packets、results、final-report 或等价记录。

### PPT退回红线

- 以下红线能在生成前识别的，白帽必须前置否决，不允许先生成再退回。
- 文字明显硬塞，像 Word 投影。
- 字号过小、行距过密、留白不足。
- 正文遮挡模板元素。
- 残留占位拉丁文、输入小标题、旧页内容。
- 连续多页机械套同一模板。
- 没导出预览或缩略总览就说完成。
- 用户要求真 PPTX 或参考现有 PPTX 时，每页只有一张整图、没有可编辑文字/形状/复用 PPT 元素，直接退回。
- 用户要求参考风格/框架/架构/版式时，只借颜色背景、不继承页型节奏、结构、可复用元素，直接退回。
- 参考 deck 有大量教学插图、案例图、公式图、示意图、image2 多文字教学图，而成品退化成纯卡片框和文字列表，直接退回。
- 参考 deck 有可复用表格、图标、卡片、图框、流程箭头、章节页、背景装饰，但成品全部低配自创且风格不搭，直接退回。
- 预览总览一眼低质、廉价、同质或明显弱于参考 deck，不能以“文件可打开、页数正确、备注已写入”放行。
- 没有 pilot page，或 pilot 明显不合格却继续批量生成，直接否决。

### UI/HTML退回红线

- 页面像默认模板或 AI slop。
- 移动端崩坏。
- 控制台 error 未解释。
- 关键按钮是假按钮。
- 缺空状态、加载态、错误态。
- 未用 Browser 或等效方式验证重要页面。

### 代码退回红线

- 构建/测试/lint 可跑却没跑。
- 修 bug 无复现或回归验证。
- 安全相关改动没有安全主帅复核。
- 依赖/许可证不明。
- 命令、路径、文档不可执行。

## 性能基准官

### 指标

- token 输入/输出。
- 缓存命中。
- 首 token 耗时。
- 总耗时。
- 重试次数和失败率。
- 接口成本。
- 构建/渲染/运行时性能。

### 规则

- 没有对照组，不说“更快”。
- 同样任务、同样样本、同样通道才可比较。
- 区分首 token 和总耗时。
- 区分单次抖动和稳定收益。
- 优化收益必须大于新增复杂度。
- PPT/文档/图片等非代码任务超过 15 分钟无实质成品推进，要记录为空转风险；超过 30 分钟仍未产出可验成品，默认判定交付节奏失败。
- PPT pilot page 应在三张表完成后快速产生；pilot 两轮不过线，继续批量生成只会放大损失，必须停。

## Skill 蒸馏退回红线

- 只看文章介绍，没有查看官方仓库、源码或规则正文。
- 没有记录 checked commit / version / checked_at。
- 没有检查许可证，却复制或改写上游大段内容。
- 不能说明吸收后解决哪个失败模式。
- 把外部 skill 当成新入口叠加。
- 同一规则在多个 unit 重复出现，形成补丁式叠加。
- 没有验证就宣称“已经融合完成”。

## 当前专家

- `白帽纠察官`：前置封驳和路线否决。
- `质检主帅`：最终验收和交付放行。
- `性能基准官`：速度、成本、token、性能基准。
