# 进化部 — OODA 自动进化 + 蒸馏师团 + 复盘学习

## 核心理念

```text
不是：执行完就结束
也不是：看到新 skill 就往身上堆
而是：执行 -> 复盘 -> 查源 -> 蒸馏 -> 验证 -> 入库 -> 下次更好
```

进化部的目标是让无极军团越用越稳、越用越省 token，而不是越长越臃肿。

## 模块一：OODA 自动进化环

```text
Observe 观察：记录执行结果、失败模式、用户反馈、外部来源
Orient  判断：定位根因、查官方源、判断重叠和风险
Decide  决策：absorb / defer / reject / rollback
Act     行动：更新唯一主责 unit 或 expert，验证后入库
```

### 触发时机

| 时机 | 触发条件 | 动作 |
|---|---|---|
| 执行后 | 每次任务完成 | 记录结果摘要 |
| 出 bug 后 | 工具调用失败、输出不符合预期 | 记录失败模式 |
| 白帽审计后 | 白帽提出系统性风险 | 进入进化队列 |
| 周期触发 | 每 10 次任务 | 自动复盘分析 |
| 外部来源触发 | 用户要求蒸馏、融合、升级某 skill 或社区方案 | 交给蒸馏师团做官方源核验 |

## 模块三：蒸馏师团

蒸馏师团是进化部下属的能力升级部门，规则见 [distillation.md](distillation.md)。

它负责：

- 查官方源、最新版、源码或规则正文、许可证。
- 判断候选 skill 是否真的值得吸收。
- 抽取机制，不复制上游编制。
- 把机制落到具体师团或专家。
- 经试验场和白帽通过后再入库。

它不负责：

- 安装一堆 skill。
- 让用户选择复杂内部路线。
- 把别人的名字、组织结构、口号搬进无极军团。

### 蒸馏裁决

| 裁决 | 含义 | 后续 |
|---|---|---|
| absorb | 证据充分，能修复失败模式或明显提质提效 | 进入试验场验证和规则落地 |
| defer | 有价值但证据不足、频率不高或缺少验证 | 登记待核验，不进主链路 |
| reject | 重复、授权不清、增加复杂度或破坏主结构 | 记录原因后停止 |

## 模块四：自动优化机制

### 同类问题 >= 3 次 -> 根因分析

```text
同一失败模式出现 3 次
-> 标记为系统性问题
-> 根因分析
-> 判断是规则缺失、流程问题、工具问题还是能力缺口
-> 必要时进入蒸馏师团
-> 更新对应 unit / expert
-> 试验场验证
```

### 优化反馈路径

```text
发现可优化点
-> 分类
   -> 规则缺失：更新对应 unit 或 SKILL.md
   -> 工具问题：更新 tools 配置或使用说明
   -> 流程问题：更新 staff.md 决策树
   -> 知识不足：更新 nuwa.md 或专家索引
   -> 外部来源可借鉴：先走 distillation.md，不直接融合
-> 备份当前配置
-> 执行更新
-> 验证
-> 记录变更
```

## 模块六：与试验场协作

```text
进化部：分析 + 决策 + 归位
试验场：复现 + 对比 + 验证
白帽：前置否决 + 风险封驳
```

| 场景 | 进化部 | 试验场 |
|---|---|---|
| 新工具/新规则 | 决定是否尝试 | 负责验证 |
| 失败模式 | 根因分析 | 复现和验证修复 |
| 外部 skill 蒸馏 | 提供来源、裁决和落点 | 做对比验证 |
| 回归风险 | 决定是否回滚 | 验证回滚后是否恢复 |

## 模块七：不做什么

- 不自动修改没问题的代码。
- 不盲目升级依赖。
- 不因为一次失败就改全局规则。
- 不改铁律，铁律是硬性不可变的。
- 不把社区二手文章当成蒸馏依据。
- 不把外部 skill 无脑叠加成新入口。
- 不在没有验证前宣布“已经融合完成”。
