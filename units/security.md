# 安全局 — 多层级安全审计 + 许可证/漏洞扫描

## 核心定位
安全不是事后的，是嵌入每个环节的。情报局一审→安全局二审→贯穿全流程。

---

## 一、安全审计层级

### L1: 代码安全扫描（每次代码修改时自动执行）
| 检查项 | 检查方式 | 红线 |
|--------|---------|------|
| 硬编码密钥 | 正则匹配 `(api_key|secret|password|token)\s*=` | ❌ 零容忍 |
| SQL注入 | 检查字符串拼接SQL | ❌ 必须用参数化 |
| 路径遍历 | 检查文件路径拼接 | ❌ 必须用安全API |
| 命令注入 | 检查shell命令拼接 | ❌ 必须用参数化 |

### L2: 依赖安全审计（每周/每次新增依赖时）
```
# Rust
cargo audit          # 检查已知漏洞
cargo deny check     # 检查许可证+漏洞

# JavaScript
npm audit            # 检查已知漏洞

# Python
pip-audit            # 检查已知漏洞
safety check         # 安全检查
```

### L3: 封装安全（发布前）
| 级别 | 措施 | 适用场景 |
|------|------|---------|
| L1 | 代码混淆 | 开源但不想被轻易抄 |
| L2 | UPX压缩+混淆 | 减小体积+基础保护 |
| L3 | 反调试+完整性校验 | 商业软件 |
| L4 | Tauri编译(Release) | 正式发布 |
| L5 | Tauri编译+加密通信 | 高安全要求 |

## 二、许可证合规检查

### 许可证兼容性矩阵
| 项目许可证 | 允许依赖的许可证 |
|-----------|----------------|
| MIT | MIT, Apache-2.0, BSD, Unlicense |
| Apache-2.0 | Apache-2.0, MIT, BSD, Unlicense |
| GPL-3.0 | GPL-3.0, MIT, Apache-2.0 (需兼容) |
| AGPL-3.0 | AGPL-3.0, MIT (需注意) |
| 商业闭源 | MIT, Apache-2.0, BSD, Unlicense, LGPL |

### 检查命令
```bash
cargo deny list                     # 列出所有依赖许可证
cargo deny check licenses           # 检查许可证合规
npx license-checker --summary       # JS项目
```

## 四、安全红线（不可违反）

1. ❌ 不复制有版权代码（只参考不复制）
2. ❌ 不存储API密钥在代码中
3. ❌ 不使用已知有漏洞的依赖
4. ❌ 不忽略许可证冲突
5. ❌ 不发布未经验证的安全封装

## 五、MCP/插件准入安全门

新增 skill、MCP、ComfyUI 自定义节点、Codex 市场插件时，默认先走安全准入，不直接融合。

| 类型 | 必查项 | 红线 |
|------|--------|------|
| MCP Server | 命令执行边界、stdio参数注入、权限范围、维护状态 | 不接入来历不明或默认高权限服务 |
| ComfyUI节点 | `install.py`、`requirements.txt`、文件写入路径、模型下载源 | 不运行未审查安装脚本 |
| Codex插件 | OAuth权限、数据读取范围、外部写入权限 | 不授权超出任务需要的权限 |
| GitHub skill | Star/维护频率/License/Issue安全反馈 | 不接入无许可证或高风险仓库 |
