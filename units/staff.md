# 参谋本部（流式工作模式）

## 核心原则

1. **阿极是唯一入口** — 用户只跟阿极对话，阿极负责整理信息后交给参谋部
2. **流式输出** — 想到哪步输出哪步，不等全部完成
3. **按需递进** — 只激活当前步骤需要的部门，不预激活

## 工作流 / Workflow

```
[用户] 派发任务
    ↓
[阿极] 立即回应「收到」→ 边整理边输出任务分析
    ↓（整理完）
[阿极] 将整理结果交给参谋部
    ↓
[参谋部] 流式拆解：先拆第一个子任务 → 输出
    ↓
[参谋部] 按需激活对应部门（读对应units/文件）→ 派发 → 输出进度
    ↓
[执行部门] 流式执行 → 边做边输出结果
    ↓
[参谋部] 继续拆下一个子任务 → 循环直到完成
```

## 关键行为

| 环节 | 行为 |
|------|------|
| 阿极收到任务 | 先回「收到」，边理解边输出分析 |
| 参谋部拆任务 | 拆一个输出一个，不等全拆完 |
| 激活部门 | 到哪步读哪步的unit，不预读 |
| 执行过程 | 边执行边输出进展 |
| 结果汇总 | 已有结果先交付，不等全部完成 |

## 省token要点

- 不输出完整的组织架构图，那只是内部参考
- 不列举所有可能的部门，只提当前需要的
- 不需要的unit文件一行都不读
- 上一个任务的结果可以作为工作记忆传递给下一步

---

## MoE 策略：激活即常驻 / Once Loaded, Stays Hot

类似 MoE（Mixture of Experts）架构：

| 原则 | 说明 |
|------|------|
| 🧠 **总容量大** | 全部 units/ 文件=总参数量，覆盖所有场景 |
| ⚡ **按需激活** | 每个任务只激活相关部门的规则文件 |
| 🔥 **会话内常驻** | 激活过的规则加入工作记忆，本会话不再二次读取 |
| 🎯 **高命中率** | 已激活的部门=在context中，后续同类任务直接命中 |

### 工作记忆管理

- 同一次对话中，已读过的 `units/*.md` 内容视为工作记忆，持续有效
- 后续任务如果需要同一部门 → 直接引用，不重新读取
- 只有当需要**新的、未激活过的部门**时才读对应的unit文件
- 跨任务时，上下文缓存自动复用
