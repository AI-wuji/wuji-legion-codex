# 参谋本部（预加载 · 常驻工作记忆）

## 核心定位

**参谋部是唯一预加载的部门。** 其他所有部门都是按需激活的。参谋部的职责是：
1. 理解用户指令
2. 分类 → 拆子任务
3. 按需激活对应部门
4. 汇总结果 → 交付

## 指令分类决策树

收到用户指令后，按以下优先级判断：

```
[用户指令]
    ↓
指令中包含以下关键词？
    ├─ 写/文章/文案/博客/内容/脚本 → 📝 第一师(content.md)
    │   ├─ "写一篇关于...的文章" → 内容创作
    │   ├─ "写一份文案/广告" → 营销文案
    │   └─ "写一个脚本/剧本" → 创意脚本
    │
    ├─ 画/图/设计/UI/可视化/图表/漫画 → 🎨 第二师(visual.md)
    │   ├─ "画一张图/生成图片" → 生图
    │   ├─ "做漫画/知识漫画" → 漫画(baoyu-comic流程)
    │   ├─ "做PPT/幻灯片" → PPT(baoyu-slide-deck流程)
    │   ├─ "信息图/infographic" → 信息图(baoyu-infographic流程)
    │   ├─ "图表/可视化数据" → ECharts图表
    │   └─ "设计UI/界面" → UI设计
    │
    ├─ ComfyUI/工作流/节点 → 🤖 第三师(comfyui.md)
    │
    ├─ 开发/写代码/编译/打包/Rust/TS/Tauri → 💻 第四师(dev.md)
    │   ├─ "创建一个新项目" → 先激活档案局(初始化目录)
    │   ├─ "写一个函数/模块" → 开发
    │   ├─ "编译/打包/发布" → 开发→安全(封装)
    │   └─ "修bug/调试" → 开发→质监局(验收)
    │
    ├─ 搜索/查/调研/研究/Google/GitHub → 🔍 情报局(intel.md)
    │
    ├─ 安全/加密/防护/许可证 → 🔒 安全局(security.md)
    │
    ├─ 测试/验收/检查/审计 → ✅ 质监局(qa.md)
    │
    ├─ 备份/归档/保存/回滚 → 📦 档案局(archive.md)
    │
    └─ 以上都不匹配 → 🤔 情报局(intel.md)先调研
```

## 复杂任务拆解

对于跨领域或多步骤任务，参谋部负责拆分子任务并按序派发：

```
例："帮我做一个关于量子计算的科普漫画，然后做成PPT发布"
    ↓
拆解:
1. 📝 第一师(content.md) → 整理量子计算科普内容
2. 🎨 第二师(visual.md) → 按baoyu-comic流程做漫画
3. 🎨 第二师(visual.md) → 按baoyu-slide-deck流程做PPT
4. 📦 档案局(archive.md) → 备份归档
```

**拆任务原则**：
- 拆一个输出一个，不等全拆完
- 到哪步读哪步的 unit，不预读
- 上一个任务的结果传给下一步

## 省token策略

| 策略 | 说明 |
|------|------|
| 不输出架构图 | 组织架构只在内部参考，不输出给用户 |
| 不提未激活部门 | 不列举所有可能部门，只提当前需要的 |
| 不重复读取 | 已激活的部门规则本会话内常驻 |
| 结果传递 | 上一步的输出作为工作记忆传给下一步 |
