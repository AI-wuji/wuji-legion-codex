## 二、动态组队算法

### 组队规则
1. **主专家** — 与任务类型最匹配的专家（最高分）
2. **辅助专家** — 补充主专家的盲区（跨领域互补）
3. **白帽纠察专家** — 每个团队自动配备一个反对者

### 并行派发规则
```
独立任务 → 所有专家同时执行
协作任务 → 主专家先执行，辅助并行跟进
复合任务 → 按依赖关系分阶段并行
```

## 四、并行执行协调协议

### Agent间通信格式
当多个专家并行执行时，通过共享上下文交换信息：

```json
{
  "task_id": "TASK-20260524-001",
  "lead_expert": "zhang-yiming",
  "assist_experts": ["linus-torvalds", "john-carmack"],
  "shared_context": {
    "input": "设计一个高性能Rust Web框架",
    "constraints": ["异步优先", "内存安全"],
    "output_format": "architecture.md"
  },
  "parallel_mode": "independent",
  "deadline": null
}
```

### 冲突解决
当多个专家给出不同意见时：
1. 主专家有最终决定权
2. 白帽纠察意见必须记录但可被否决（需说明理由）
3. 无法解决的争议 → 升级到MoE中枢 + 人类仲裁

## 八、多Agent协同调度协议（v4.0 · 借鉴Agency NEXUS体系）

### 激活流程
参谋部MoE判定需求 → 按人才激活表找到匹配专家
  - 需要1个专家 -> 直接激活（提供标准激活结构）
  - 需要多个专家 -> 组建团队，分配主/辅角色
  - 需要流水线 -> 按阶段依次激活

每个专家收到统一格式的激活指令（含上下文+期望输出）
专家执行 -> 输出标准格式结果 -> 交下一个专家或汇总
质量门：每个阶段输出必须通过验收才能进入下一阶段
最多3次重试 -> 仍然失败则升级到参谋部

### Handoff协议
`
# Handoff
## Metadata
- 来自: [专家A] -> 交给: [专家B]
- 任务: [任务描述]
- 优先级: [高/中/低]

## 上下文
- 已完成: [已完成的工作]
- 关键文件: [文件列表]
- 待解决: [未完成的问题]

## 交付要求
- 期望输出: [具体描述]
- 质量要求: [验收标准]
`

### 质量门（Quality Gate）
每个阶段交付物必须满足：
  - 功能完整
  - 白帽纠察已审查（至少3个反对意见已处理）
  - 安全无风险
  - 可交付下一阶段
不通过 -> 退回修改（最多3次）-> 否则升级到参谋部
