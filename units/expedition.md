# 远征军调度室 — 多工兵并行外派 + Handoff标准化

## 核心定位
当任务可分解为多个独立子任务时，并行派发给多工兵执行，大幅提效。

---

## 一、并行外派协议

### 外派条件判断

```
[参谋部判定]
    ↓
检查外派条件：
  ├─ 任务是独立子任务？ → 可并行外派
  ├─ 有明确spec？ → 可外派
  ├─ 需要人类判断？ → 不可外派
  ├─ 影响核心架构？ → 不可外派
    ↓
可外派 → 拆分为N个子任务 → 并行派发
不可外派 → 内部执行
```

### 适合外派的任务
| 任务类型 | 并行度 | 说明 |
|---------|--------|------|
| 样板代码生成 | 高 | 多文件可同时生成 |
| 单元测试编写 | 高 | 每个测试独立 |
| 搜索调研 | 中 | 多引擎并行搜索 |
| 文档编写 | 中 | 章节可并行 |
| 图像/视频渲染 | 中 | ComfyUI批量 |
| 代码格式化/lint | 高 | 自动化工具 |

### 不适合外派的任务
| 任务类型 | 原因 |
|---------|------|
| 架构设计 | 需要全局视角 |
| 代码Review | 需要理解上下文 |
| 安全审计 | 需要专业知识 |
| 白帽纠察批判 | 需要整体判断 |

## 二、并行派发流程

```
[主任务拆分为N个子任务]
    ↓
为每个子任务生成独立spec（含上下文+输出要求）
    ↓
并行派发（Promise.allSettled）：
  ├─ 工兵A: 子任务1
  ├─ 工兵B: 子任务2
  ├─ 工兵C: 子任务3
  └─ ...
    ↓
逐个子任务验收（质监局）
    ↓
合并结果 → 生成handoff文档
```

### Spec模板
```markdown
## 任务Spec
- 任务ID: EXP-{日期}-{序号}
- 父任务: {主任务描述}
- 具体内容: {详细说明}
- 输出格式: {要求格式}
- 依赖项: {需要的前置条件}
- 上下文: {背景信息/代码库}
```

### Handoff文档模板
```markdown
## Handoff报告
- 任务ID: EXP-{日期}-{序号}
- 完成状态: ✅ 完成 / ❌ 部分完成 / ❌ 失败
- 修改文件: {文件列表}
- 未完成事项: {如果有}
- 已知问题: {已知限制/未解决的问题}
- 下一步: {建议的后续操作}
```

## 六、并行执行状态协议（多Agent进度跟踪）

### 状态报告格式
每个并行执行的部门/工兵定期报告状态：

```
状态: [部门名]
任务: [当前任务]
进度: [0-100]%
问题: [如果有]
预计完成: [时间]
```

### 状态等级
| 状态 | 含义 | 行动 |
|------|------|------|
| 🟢 进行中 | 正常执行 | 不干预 |
| 🟡 遇到问题 | 有阻塞但可自行解决 | 关注 |
| 🔴 阻塞 | 无法继续，需要帮助 | 参谋部介入 |
| ✅ 完成 | 任务完成 | 进入验收 |

### 超时机制
| 任务类型 | 超时阈值 | 超时后的行动 |
|---------|---------|-------------|
| 简单任务 | 5分钟 | 标记为🟡，询问是否需要帮助 |
| 中等任务 | 15分钟 | 标记为🟡，询问是否需要帮助 |
| 复杂任务 | 30分钟 | 标记为🔴，参谋部介入 |

### 多Agent并行时的状态汇总
```
执行计划: [原始计划]
当前状态:
  ├─ 🟢 dev.md: 完成60% (预计10分钟后)
  ├─ 🟡 visual.md: 遇到设计风格选择问题 (参谋部待决策)
  └─ ✅ intel.md: 已完成
阻塞项: visual.md风格选择 — 等待参谋部
```
