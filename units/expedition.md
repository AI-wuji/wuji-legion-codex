# 远征军调度室（已加载至工作记忆）

## 适用场景

接到任务后，判断是否适合外派。适合外派的情况：

| 适合外派 | 不适合外派（留在Codex本地做） |
|---------|---------------------------|
| 大量样板代码/CRUD | 架构设计/策略分析 |
| 明确spec的功能实现 | 代码Review/质量验收 |
| 软件包安装/卸载 | 复杂调试排错 |
| 搜索引擎查资料 | 用户需求分析 |
| 文件加解密/打包 | spec文档写作 |
| 网络请求/API调用 | UI/UX 审美判断 |

## 工兵档案

### 工兵L — Local 35B
- **用途**：代码编写/重构/文档生成
- **模型**：本地 Qwen 3.6 35B MoE（127.0.0.1:8080）
- **成本**：免费，零排队
- **特点**：风格一致，适合大量体力活
- **CLI启动**：`trae-cn --user-data-dir ".trae-local" chat --mode agent --add-file <spec> <prompt>`

### 工兵C — Cloud Auto
- **用途**：搜索/安装/加解密/网络操作
- **模型**：Trae 云端自动（不排队）
- **成本**：免费额度内
- **特点**：快速，联网，能跑命令
- **CLI启动**：`trae-cn --user-data-dir ".trae-cloud" chat --mode ask --add-file <spec> <prompt>`

## 外派流程

```
[参谋部] 判断任务适合外派
  |
  v
[参谋部] 写 spec 文件到 tasks/incoming/
  |  spec 包含：任务描述、验收标准、输出路径、时间预估
  v
[阿极] 调 dispatch 脚本
  |  dispatch.ps1 -Target L|C -Spec tasks/incoming/xxx.md
  |  内部：trae-cn ... chat --mode agent --add-file ...
  v
[工兵] Trae 接收 spec → 执行 → 修改文件
  |  Trae GUI 自动弹窗干活，无需人工介入
  v
[阿极] dispatch 脚本轮询等待
  |  检测文件变更 + 稳定后返回
  v
[质监局] code review
  |  合格 → 汇总结果
  |  不合格 → 写 fix spec → 重新派
  v
[参谋部] 汇总到用户
```

## spec 格式规范

每次外派必须生成 `.md` spec 文件，包含以下内容：

```markdown
# 任务名称

## 背景
为什么做、相关文件、项目上下文

## 要求
- [要求1]
- [要求2]

## 实现方案
- 做什么
- 不做什么（防跑偏）
- 注意事项

## 输出文件清单
- [路径1] — 创建或修改，内容说明
- [路径2] — 创建或修改，内容说明

## 验收标准
- [ ] 标准1
- [ ] 标准2

## 技术约束
- 遵循无极军团代码规范
- 不修改未列出的文件
- X分钟后未完成应输出进度
```

## 省 token 策略（核心）

| 环节 | token消耗 | 说明 |
|------|----------|------|
| 需求分析 | 高 | 必须Codex做，无法省 |
| spec写作 | 中 | Codex做 |
| 代码实现 | **极高** | → 外派给工兵L，免费 |
| 代码review | 高 | 必须Codex做，无法省 |
| 搜索调研 | 中 | → 外派给工兵C |
| 安装部署 | 低 | → 外派给工兵C |
| 质量验收 | 中 | Codex做 |
| 结果汇报 | 低 | 无需满token输出 |

**预估节token比例**：重体力项目可节省 60-80% 的 token 消耗。
