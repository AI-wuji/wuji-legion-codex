# 远征军调度室 — 多工兵并行外派 + Handoff标准化

## 核心定位
当任务可分解为多个独立子任务时，并行派发给多工兵执行，大幅提效。

---

## 一、并行外派协议

### 外派条件判断

```
[参谋部判定]
    ↓
检查外派条件：
  ├─ 任务是独立子任务？ → 可并行外派
  ├─ 有明确spec？ → 可外派
  ├─ 需要人类判断？ → 不可外派
  ├─ 影响核心架构？ → 不可外派
    ↓
可外派 → 拆分为N个子任务 → 并行派发
不可外派 → 内部执行
```

### 适合外派的任务
| 任务类型 | 并行度 | 说明 |
|---------|--------|------|
| 样板代码生成 | 高 | 多文件可同时生成 |
| 单元测试编写 | 高 | 每个测试独立 |
| 搜索调研 | 中 | 多引擎并行搜索 |
| 文档编写 | 中 | 章节可并行 |
| 图像/视频渲染 | 中 | ComfyUI批量 |
| 代码格式化/lint | 高 | 自动化工具 |

### 不适合外派的任务
| 任务类型 | 原因 |
|---------|------|
| 架构设计 | 需要全局视角 |
| 代码Review | 需要理解上下文 |
| 安全审计 | 需要专业知识 |
| 红队批判 | 需要整体判断 |

---

## 二、并行派发流程

```
[主任务拆分为N个子任务]
    ↓
为每个子任务生成独立spec（含上下文+输出要求）
    ↓
并行派发（Promise.allSettled）：
  ├─ 工兵A: 子任务1
  ├─ 工兵B: 子任务2
  ├─ 工兵C: 子任务3
  └─ ...
    ↓
逐个子任务验收（质监局）
    ↓
合并结果 → 生成handoff文档
```

### Spec模板
```markdown
## 任务Spec
- 任务ID: EXP-{日期}-{序号}
- 父任务: {主任务描述}
- 具体内容: {详细说明}
- 输出格式: {要求格式}
- 依赖项: {需要的前置条件}
- 上下文: {背景信息/代码库}
```

### Handoff文档模板
```markdown
## Handoff报告
- 任务ID: EXP-{日期}-{序号}
- 完成状态: ✅ 完成 / ❌ 部分完成 / ❌ 失败
- 修改文件: {文件列表}
- 未完成事项: {如果有}
- 已知问题: {已知限制/未解决的问题}
- 下一步: {建议的后续操作}
```

## 三、与各部门协作

| 协作方 | 交互方式 |
|--------|---------|
| 参谋本部(MoE) | 接收外派指令 + 交付handoff报告 |
| 第四师(开发) | 代码类外派的spec编写 |
| 质监局 | 验收外派结果 |
| 档案局 | 归档handoff文档 |
| 试验场 | 外派新工具测试 |

## 四、repomix打包集成

当外派需要完整项目上下文时：
```bash
npx repomix --output repomix-output.xml
# 将output.xml附在spec中一起派发
```
