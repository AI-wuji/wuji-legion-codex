# 试验场 — 沙箱化测试 + 对比评估 + 融合验证

## 核心定位
所有新技能/工具/工作流在正式融合前，必须经过试验场验证。沙箱化运行，不影响在产系统。

---

## 一、试验流程

```
[新技能/工具]
    ↓
① 情报局搜索→安全局二审→参谋部判定可试
    ↓
② 试验场沙箱化运行：
  ├─ 场景1: 真实场景复现
  ├─ 场景2: 压力测试（边界条件）
  └─ 场景3: 与现有方案对比
    ↓
③ 评估报告 → 质监局验收 → 红队审计
    ↓
④ 通过 → 正式融合 | 不通过 → 记录到进化部
```

---

## 二、评估标准

| 维度 | 评分标准（1-5） |
|------|----------------|
| 功能完整性 | 功能是否按预期工作 |
| 性能表现 | 速度/资源消耗对比 |
| 兼容性 | 与现有系统是否有冲突 |
| 可维护性 | 文档/代码质量 |
| 安全等级 | 安全局评估结果 |

### 对比测试表
```markdown
| 维度 | 现有方案 | 新方案 | 差异 |
|------|---------|--------|------|
| 速度 | X ms | Y ms | +-Z% |
| 质量 | X/5 | Y/5 | +-Z |
| 资源占用 | X MB | Y MB | +-Z% |
| 复杂度 | X/5 | Y/5 | +-Z |
```

---

## 三、融合决策树

```
[评估报告完成]
    ↓
评估总分：
  ├─ ≥4分 → ✅ 直接融合
  ├─ 3-4分 → ⚠️ 有条件融合（记录风险点）
  └─ <3分 → ❌ 拒绝融合（记录原因，进化部复盘）
```

### 融合后跟踪
融合后7天内自动跟踪是否有回归问题，如有问题自动回滚。

---

## 四、与各部门协作

| 协作方 | 交互方式 |
|--------|---------|
| 参谋本部(MoE) | 接收测试指令+交付评估报告 |
| 情报局 | 接收待测工具的技术调研 |
| 安全局 | 安全评估 |
| 质监局+红队 | 结果验收+反对意见 |
| 进化部 | 失败记录+经验积累 |
| 档案局 | 存档评估报告 |

---

## 五、快速测试（简化版）

对于小修改/低风险融合：
```
小修改 → 档案局备份 → 直接融合（跳过完整试验流程）
大修改/新技术 → 必须走完整试验场流程
```
