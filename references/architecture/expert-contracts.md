# 专家契约与 MoE 路由

无极军团采用“静默专家、按需唤醒”的 MoE 结构。专家不是常驻模型，也不是第二个用户入口，而是**参谋部执行图中的任务级执行契约**。目录见 `capabilities/experts/manifest.json`。

## 在无极军团主链中的位置

专家不是阿极的替代品，也不是独立路由器。固定顺序是：

```text
用户自然语言
  -> 阿极收集并维护需求表/需求图
  -> 阿极应用 PonyTail 最小正确原则和白帽判断
  -> 阿极把自然语言转成结构化任务语义（目标、风格、约束、验收）
  -> 形成版本化需求快照
  -> 参谋部建立任务图、确定依赖并派发
  -> 命中的领域专家把任务语义编译成该领域可执行提示词，并加载已验证 Skill/MCP/插件流程
  -> 受限执行节点完成任务
  -> 独立验证与回执
  -> 阿极对账并向用户汇报
```

豆包工作、WorkBuddy 的可借鉴点是“预置高质量领域流程，用户无需手选专家”。在无极军团中，这些预置专家只能作为参谋部任务节点的冷能力包；阿极仍负责需求理解、质疑和最终沟通，参谋部仍负责确定性派发，专家不得自行收集需求、修改需求表、派发其他专家或宣布完成。

## PonyTail 的全角色约束

PonyTail 是全链路的共同执行原则，不是阿极的人格标签。阿极、参谋部的任务分析、专家的专业思考与提示词编译、执行节点的制品生成、验证节点和最终汇报都必须遵守：

- 用最少的上下文和 token 表达足够完成任务的信息；
- 先复用现有能力、模板、依赖和工具，再新增代码或流程；
- 选择最小正确路径，避免无关分支、重复解释和无边界重试；
- 证据不足时指出不确定性，不用更长文本掩盖缺口；
- 以真实执行和验证证据为完成依据。

## 需求语义与专业提示词

阿极不应替专家临时编写所有领域细节。它先把用户话语抽取为结构化需求语义，例如“生成美女画像”至少包含主体、外观/风格偏好、构图、用途、输出尺寸、质量要求、禁用项和验收标准。随后由图像专家的固定流程把这些字段编译为绘画模型可执行的提示词、负面提示词、参数和生成/检查步骤（如适合时加入 4K、光影、镜头和材质描述）。

因此职责边界是：阿极负责忠实理解与澄清，参谋部负责把已确认语义编成任务节点，领域专家负责专业化提示词和工具流程；任何一层都不能凭空添加违背用户意图的风格或要求。

## 生命周期

```text
自然语言 -> 阿极识别场景 -> 选择 0/1 个主专家（必要时 1 个辅助专家）
          -> 装载固定 Skill/MCP/插件组合 -> 参谋部生成有界任务图
          -> 执行节点 -> 独立验证 -> 反馈账本
```

没有命中、证据不足、预算不足或白帽判断认为不合理时，专家保持缄默，阿极直接澄清、拒绝或走最小通用路径。专家不得自行唤醒其他专家、扩大权限、修改路由规则、接管需求表或宣布完成。

## 契约字段

每个专家必须声明触发词与反例、固定能力组合、允许/禁止工具、输入输出格式、时间/字节/重试预算、白帽拒绝条件和独立验收探针。固定组合是稳定先验；任务契约可以在必要时覆盖可选步骤，但不能绕过安全、证据和预算门禁。

## 进化

专家升级只接受真实失败、复用、来源和验证事件。新流程先作为候选版本运行对照测试；只有独立验证文件、SHA-256、边界复核和内容寻址 promotion receipt 齐全，才允许替换当前版本。失败候选保持可追溯但不自动进入路由。
