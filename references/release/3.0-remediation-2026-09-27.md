# 3.0 项目整改验收（2026-09-27）

范围：仅 `wuji-legion-codex-3.0` 项目目录；未改 Codex 安装态。原工作树已有用户改动，均保留。不引入 Laya，不做 A/B 验证。

当前专家体系以 `capabilities/experts/manifest.json` 和 [统一进化准入](../expert-templates/evolution-admission.md) 为准：8 位主帅、39 位专家、28 条任务级提炼方法。55 个共享入口均有[逐项决议](../expert-templates/source-decisions.json)，49 个提炼方法来源、6 个不准入；来源方法不等于完整 Skill 包已安装或运行。以下验收表保留当次项目检查的证据边界，不能当作安装态验收。

截至 2026-09-29，OfficeCLI 已按上游最新稳定版 `1.0.152` 更新锁定，SHA-256 和行为探针均已重新验证；审计脚本改为优先使用当前 PowerShell 运行时，避免 Windows PowerShell 选择错误运行库。项目路由仍不等于 Codex 宿主、剪映或 REAPER 的真实执行回执。

W5/W6 原文对照：8 位主帅即 8 个专家团，39 位专家归于单一目录；课程 W5 1.1–2.9、W6 3.1–3.12 和 4.2–4.9 的逐项映射见 `references/expert-templates/w5-w6-template-map.md`。共享目录 55 个入口的提炼或不准入决议在 `source-decisions.json`；示例报价、私有路径、六列分镜和采集权限不得当作本项目真实数据或授权。商单阶段 `commercial-decompose → commercial-quote` 串行；课程设计、学习辅导、发布交付已成为内容师团按需专家。团队阶段依赖/成员/环检测已加，但阶段表尚不能自动创建全部原生子代理并取得独立宿主回执。

新增专家的项目操作：在 `capabilities/experts/manifest.json` 记录唯一 ID、所属 capability、触发/反例、编译规则、工作流和验证；需要专属 Skill 时，把它作为该 capability 的 `optional` 且 `callable` 来源登记，专家用 `source_ids` 引用。运行路由、dispatch 的来源哈希/预算测试与真实行为探针；先获准入证据再升级生命周期，不因专家数量增加而自动晋级。

仍需单独落地：宿主实际按路由创建原生执行节点、提供可信模型/档位/执行/独立验证回执；按真实任务补逐专家行为探针；如要免费生图/生视频，明确 Agnes 的 API、认证、额度、费用和调用验证。以上都不能由路由 JSON 自称完成。

## 来源与现有能力的证据边界

55 个共享入口均有具体方法归属或不准入理由及入口哈希，见 `source-decisions.json`。其中 49 个入口的**可提炼方法**进入任务级契约，不能表述为 49 个完整 Skill 已逐脚本细读、安装或行为验证。相关二级资源在实际使用前按 `evolution-admission.md` 核对许可、平台和行为证据。

课程模板与 11 位基础专家、领域能力包和来源账合为同一谱系，没有替换 PPT/写作/研究/视觉/代码等既有入口。`source-audit` 的注册来源可用性仍以现场结果为准，保留并不意味着全部可调用。未绑定不热暴露团队名单或方法；无宿主回执时任务图保持 `planned`。此项是项目级契约修复，不是 Codex 安装态生效或原生子代理已退出的证明。
